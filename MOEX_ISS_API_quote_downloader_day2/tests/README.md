# Проверки загрузчиков

`test_day2.py` проверяет RTS и MIX без доступа к MOEX: выбор двух ближайших
контрактов с включением дня экспирации, сохранение нулевого открытого интереса,
восстановление пропусков и дней с одной строкой, отсутствие дублей, повторную
проверку пустого ответа, откат ошибочной записи и сохранность существующих данных,
границу вчерашнего дня в московском часовом поясе, пагинацию, отказ при
недополученной странице или отсутствующем столбце, сетевые ошибки и сохранность
ранее записанных дней после сетевого отказа.
Пустые будние дни проверяются повторно; кеш пустых выходных должен сохраняться
после закрытия БД и исключать повторные сетевые запросы без фиктивных котировок.
Проверяются торговая суббота, принудительная перепроверка из командной строки,
снятие отметки при появлении неполной истории, повторная проверка даты с одной
сохранённой строкой и отсутствие отметок после сетевого или структурного отказа.
Строка отдельного фьючерса с NULL, пустым или неверным ASSETCODE должна приводить
к отказу проверки, а не к сохранению ложного подтверждения пустого выходного.
Дополнительно проверяются сохранение архивных SECID с дополнительными
символами и сообщение с названием пустого поля. Ответ RTS за 03.01.2018,
предоставленный пользователем, сохранён в `fixtures/rts_history_2018-01-03.json`
для воспроизведения ошибки выбора контрактов 2019 года вместо 2018 года.
Файловые журналы проверяются на реальных временных файлах: сохранение исходных
NULL и числа сделок, выбранной пары и URL, разделение общего журнала и ошибок,
дописание при повторном запуске без дублей и сохранность БД после сетевого отказа.
В `fixtures/mix_no_trades_2018-01-12.json` сохранены исходные данные MIX из
журнала ISS за 12.01.2018 и полные строки предыдущего дня из БД пользователя.
Проверяется подстановка OHLC=227500 для `MXM8_2018`, нулевого объёма и сохранение
исходного OPENPOSITION=38; служебная отметка должна содержать исходные NULL
и дату предыдущего закрытия, а повторный запуск — пропускать сохранённую пару.
Для обоих инструментов проверяются последовательные дни без сделок через
выходные, запрет цены другого контракта или будущей даты, сохранение текущего
открытого интереса, отказ при сделках, ненулевом объёме, частичных OHLC или
отсутствующем интересе. Отказ записи `FilledQuotes` должен откатить котировки
и сохранить прежние отметки; `--recheck-filled` должен заменить свечу реальными
данными, снять отметку и обновить следующие подстановки в выбранном периоде.
Успешный перенос должен попадать в общий журнал с датой и ценой источника,
не создавая сообщения об ошибке в отдельном журнале.
Пустой ответ при принудительной перепроверке уже подставленной пары должен
возвращать код 1, сохраняя прежние котировки и служебную отметку.
При отказе проверки идентификатора история должна записываться в журнал
в исходном виде вместе с датой, кодом контракта и URL запроса.

В fixtures/mix_history_2020-12-14.json сохранён полный ответ пользователя:
два календарных спреда на RFUD имеют ASSETCODE=NULL и должны быть исключены
до проверки ASSETCODE отдельных контрактов. Проверяется запись MXZ0 и MXH1
со всеми десятью полями и без подстановок. Для обоих инструментов проверяются
спред и его контракты на разных страницах с архивными SECID, исключение спреда
с заполненным ASSETCODE и отказ без кеширования выходного, если составные коды
не подтверждены контрактами в ответе. При ошибке на ранней странице диагностика
должна сохранять именно её исходный ответ и URL после завершения пагинации.

Из корня проекта:

```powershell
python -B -m unittest discover -s MOEX_ISS_API_quote_downloader_day2/tests -v
```

Параметр `-B` отключает создание байткода, `-s` задаёт папку тестов,
`-v` включает подробный результат. Дополнительные пакеты не нужны.
