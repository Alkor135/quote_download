# Дневные котировки двух ближайших фьючерсов MOEX

В папке находятся два самостоятельных скрипта стандартного Python 3.10+.
Устанавливать `requests`, `pandas` или `apimoex` не требуется.

| Скрипт | Базовый актив ISS | Коды контрактов | БД по умолчанию |
|---|---|---|---|
| `update_futures_RTS_day2.py` | `RTS` | `RI…` | `C:\data_quote\day2\RTS_day2.db` |
| `update_futures_MIX_day2.py` | `MIX` | `MX…` | `C:\data_quote\day2\MIX_day2.db` |

## Запуск

Из корня проекта:

```powershell
python MOEX_ISS_API_quote_downloader_day2\update_futures_RTS_day2.py
python MOEX_ISS_API_quote_downloader_day2\update_futures_MIX_day2.py
```

Первый запуск загружает историю с **01.01.2018 по вчерашний день включительно**.
Вчерашняя дата определяется по московскому времени (UTC+3), независимо от
часового пояса компьютера. Даже явный `--end` не разрешает загружать текущий день.
Скрипт автоматически создаёт папку БД и таблицы, если их нет.

При повторном запуске проверяется **весь период**, а не только даты после
последней записи. Пропускаются даты с ровно двумя полными строками, а также
субботы и воскресенья с сохранённым подтверждением пустого ответа ISS.
Отсутствующий день, день с одной строкой или неверными значениями загружается
заново. Уже полные дни повторно не скачиваются и не переписываются.

Примеры ограничения периода и настройки соединения:

```powershell
python MOEX_ISS_API_quote_downloader_day2\update_futures_RTS_day2.py --start 2018-01-01 --end 2018-12-31
python MOEX_ISS_API_quote_downloader_day2\update_futures_MIX_day2.py --start 2018-01-01 --end 2018-12-31
python MOEX_ISS_API_quote_downloader_day2\update_futures_RTS_day2.py --db C:\data_quote\day2\RTS_day2.db --timeout 30 --retries 5
python MOEX_ISS_API_quote_downloader_day2\update_futures_MIX_day2.py --db C:\data_quote\day2\MIX_day2.db --pause 0.1
python MOEX_ISS_API_quote_downloader_day2\update_futures_MIX_day2.py --log-dir C:\data_quote\day2\logs
python MOEX_ISS_API_quote_downloader_day2\update_futures_RTS_day2.py --recheck-empty-weekends
python MOEX_ISS_API_quote_downloader_day2\update_futures_MIX_day2.py --start 2018-01-01 --end 2018-12-31 --recheck-empty-weekends
python MOEX_ISS_API_quote_downloader_day2\update_futures_MIX_day2.py --recheck-filled
python MOEX_ISS_API_quote_downloader_day2\update_futures_RTS_day2.py --recheck-filled --recheck-empty-weekends
python MOEX_ISS_API_quote_downloader_day2\update_futures_RTS_day2.py --help
python MOEX_ISS_API_quote_downloader_day2\update_futures_MIX_day2.py --help
```

| Параметр | Назначение | По умолчанию |
|---|---|---|
| `--start` | Первая проверяемая дата включительно, `ГГГГ-ММ-ДД`; не раньше 2018 года | `2018-01-01` |
| `--end` | Последняя проверяемая дата включительно, не позже вчерашней московской даты | Вчера по Москве |
| `--db` | Путь к собственной SQLite БД инструмента | См. таблицу выше |
| `--log-dir` | Папка файловых журналов UTF-8 | `logs` рядом со скриптом |
| `--recheck-empty-weekends` | Запросить заново все подтверждённые пустые выходные в заданном периоде | Отключён |
| `--recheck-filled` | Перепроверить все даты с подставленными OHLC в заданном периоде и обновить пару | Отключён |
| `--timeout` | Положительный тайм-аут сетевой операции, секунды | `20` |
| `--retries` | Число попыток одного запроса, включая первую | `4` |
| `--pause` | Неотрицательная пауза после успешного запроса, секунды | `0.05` |

## Выбор контрактов и полнота

1. Запрос дневной истории
   `https://iss.moex.com/iss/history/engines/futures/markets/forts/securities.json`
   с `date`, `assetcode` и пагинацией `start`. Получаются все страницы.
   Отсутствующий обязательный столбец, пустой `BOARDID`, `TRADEDATE` или `SECID`, неверная дата или недополученная
   страница считаются ошибкой ответа, а не отсутствием торгов.
2. Используются фьючерсы на доске `RFUD` с соответствующим `ASSETCODE`:
   `RTS` или `MIX`. `SECID` не ограничивается шаблоном короткого торгового кода:
   архивные обозначения, например `RIH8_2018` и `RIM8_2018`, сохраняются целиком.
   Другие доски и базовые активы исключаются. На самой доске RFUD также бывают
   календарные спреды, например MXH1MXM1 и MXZ0MXH1 в ответе MIX за 14.12.2020,
   у которых ASSETCODE=NULL. После получения всех страниц исключаются строки,
   чей SECID составлен из двух разных SECID одного актива, присутствующих
   в этом ответе. Это правило действует и при заполненном ASSETCODE спреда.
   Полные коды отдельных контрактов не обрезаются и не ограничиваются шаблоном.
   У остальных строк RFUD ASSETCODE должен быть непустой строкой: неверное значение
   остаётся ошибкой и не превращается в подтверждение пустого выходного.
   Исключённые спреды перечисляются в общем журнале на уровне INFO.
3. Из описания `https://iss.moex.com/iss/securities/{SECID}.json` берутся
   реальные `SHORTNAME` и `LSTTRADE`. Описания кешируются в самой БД.
   Отсутствующая экспирация не заменяется произвольной будущей датой.
4. Среди контрактов с `LSTTRADE >= TRADEDATE` выбираются два с минимальной
   `LSTTRADE`. При совпадении сроков порядок определяется `SECID`.
   **Последний день торгов включается**, нулевой `OPENPOSITION` сохраняется.
5. Только после выбора проверяются все десять полей пары. Если ближайший
   контракт содержит `NULL`, он не заменяется более дальним контрактом.
   Для дня без сделок допускается перенос предыдущего закрытия по правилу ниже.
   Если после этого пара неполная, день не записывается; ошибка отражается в журнале и коде выхода.
6. Две строки дня записываются одной транзакцией. Если этот день уже содержал
   неполные данные, они заменяются только при успешной записи полной пары.
   При ошибке прежние строки сохраняются.

Перебираются календарные даты, включая выходные: Московская биржа может
проводить торги в необычные дни. День недели сам по себе не разрешает пропуск.
Если успешный запрос всех страниц не вернул истории за субботу или воскресенье,
дата и время проверки сохраняются в `EmptyWeekends`. Только такие даты
пропускаются при обычных повторных запусках. Пустые будние дни, сетевые ошибки
и дни с неполными котировками продолжают проверяться каждый раз.

Отдельной отметки «загружено» для котировок нет: скрипт проверяет наличие
ровно двух полных строк в `Day`. `EmptyWeekends` хранит подтверждения пустых
выходных; фиктивные строки котировок для них не создаются. Наличие любых строк
`Day`, в том числе единственной строки, исключает использование отметки пустоты.

Если отметок пустых выходных ещё нет, первый запуск запрашивает и кеширует их;
ускорение проявляется при последующих запусках. Если биржа позднее опубликует
историю за отмеченный выходной, обычный запуск её не обнаружит. Для повторной
проверки всех таких дат используйте `--recheck-empty-weekends`; `--start` и `--end`
ограничивают её период. Непустой ответ снимает отметку пустоты, даже если котировки
ещё неполны. Полные дни с двумя строками при этом по-прежнему пропускаются.
Таблица добавляется в существующую БД автоматически, данные `Day` сохраняются.

Для существующей `C:\data_quote\day2\RTS_day2.db` 06.10.2026 уже перенесены
906 подтверждённых пустых выходных из последнего завершённого журнала RTS.
Время `CHECKED_AT` взято из соответствующих сообщений журнала; все 4404 строки
`Day` сравнены до и после переноса и совпали. Поэтому следующий обычный запуск
RTS уже использует эти отметки. MIX заполняет свой кеш при следующем запуске.
Код выхода `0` означает отсутствие известных ошибок, но не подтверждает, что
каждый пустой ответ ISS действительно соответствует нерабочему дню.

Сетевые запросы повторяются с возрастающими паузами. При исчерпании попыток
скрипт останавливается с кодом `1`, сохраняя ранее записанные полные дни.
Некорректная пара пропускается с ошибкой; проверка остальных дат продолжается.
Прерывание пользователем возвращает `130`. Для продолжения достаточно
повторить обычную команду: будут проверены все оставшиеся пропуски.

## Подстановка предыдущего закрытия для дня без сделок

Правило включено по умолчанию в обоих скриптах. Подстановка разрешена только,
если `NUMTRADES = 0`, **все четыре** поля `OPEN`, `LOW`, `HIGH`, `CLOSE` равны
`NULL`, а `VOLUME` равен `NULL` или числовому нулю. В `Day` ищется последняя
строка с **тем же полным SECID** и датой строго меньше текущей. Её конечное
числовое `CLOSE` переносится во все четыре OHLC, а `VOLUME` устанавливается в `0`.
`OPENPOSITION` берётся из текущего ответа ISS и не переносится из прошлого.

Выходные и промежутки между доступными датами не мешают поиску. Предыдущая
подставленная свеча тоже может служить источником: последовательные дни без
сделок получают одну цену с отдельной отметкой каждого переноса.
Если предыдущего закрытия в `Day` нет, оно некорректно или отсутствует текущий
`OPENPOSITION`, день остаётся неполным и проверяется при следующих запусках.
Дополнительный поиск прежних котировок в ISS за пределами имеющейся БД не выполняется.
Для первоначальной загрузки узкого периода может потребоваться сначала загрузить
более ранние даты, чтобы предыдущее закрытие уже находилось в БД.

Это **условные свечи**, их цены подставлены из прошлого. Таблица `FilledQuotes`
сохраняет SECID и дату свечи, дату и цену источника, исходную строку ISS в JSON
со всеми `NULL`, а также время записи. Две строки `Day` и отметки подстановок
сохраняются одной транзакцией. При отказе любой вставки прежние данные и отметки
сохраняются; незаписанные подстановки не отмечаются.

Например, для `MXM8_2018` за 12.01.2018 из закрытия 11.01.2018 получается
`OPEN = LOW = HIGH = CLOSE = 227500`, `VOLUME = 0`, `OPENPOSITION = 38` из ISS.
При ненулевом числе сделок, ненулевом объёме или частично заполненных OHLC
правило не применяется. `SETTLEPRICE` никогда не используется вместо закрытия.

Обычная докачка считает пару с разрешённой подстановкой заполненной и пропускает её.
Для проверки поздних исправлений биржи используйте `--recheck-filled`:
все отмеченные даты заданного периода запрашиваются вновь в хронологическом порядке.
Если реальные котировки появились, они заменяют условную свечу, а её отметка удаляется.
Если сделок по-прежнему нет, подстановка выполняется по последнему доступному закрытию
на момент этой проверки. Ошибка перепроверки сохраняет прежнюю пару и отметки.
Пустой ответ для уже отмеченного дня также считается неудачной перепроверкой:
скрипт возвращает код `1` и предлагает повторить `--recheck-filled`; обычная
докачка продолжает пропускать ранее сохранённую полную пару.

Подстановка отражается в общем журнале на уровне `INFO`; счётчик
`подставленных свечей` относится только к успешно записанным строкам текущего запуска.

## Пустые цены и журналы ошибок

Завершённый торговый день не гарантирует наличие сделок по каждой серии.
Если по ближайшему контракту нет сделок (`NUMTRADES = 0`), ISS может вернуть
`NULL` в `OPEN`, `LOW`, `HIGH`, `CLOSE` и `VOLUME`. Это отличается от сетевого
сбоя: ответ получен, но фактической цены сделки нет. Одно сообщение о пустом
`OPEN` само по себе ещё не доказывает отсутствие сделок; нужно смотреть
`NUMTRADES` и остальные исходные поля.

Скрипт сохраняет полную пару с допустимыми подстановками, отмеченными отдельно.
Предыдущее закрытие используется только по правилу дня без сделок выше.
Цены не заменяются нулями или `SETTLEPRICE`, ближайшая серия не подменяется дальней.
Значения `NUMTRADES` и `SETTLEPRICE` запрашиваются для диагностики и не добавляются
в таблицу `Day`. Если день не записан, повторный запуск проверит его снова.

По умолчанию журналы находятся в
`C:\Users\Alkor\VSCode\quote_download\MOEX_ISS_API_quote_downloader_day2\logs`:

| Файл | Содержимое |
|---|---|
| `RTS_day2.log` / `MIX_day2.log` | Общий ход загрузки и диагностика ошибок |
| `RTS_day2_errors.log` / `MIX_day2_errors.log` | Предупреждения, сетевые отказы, неполные дни, неожиданные исключения |

После сообщения о неполном дне в файле записывается JSON с `ASSETCODE`,
`TRADEDATE`, причиной отказа, URL истории, выбранными контрактами,
исходными строками ISS и описаниями контрактов. Поле `no_trades` перечисляет
выбранные серии с `NUMTRADES = 0`. В JSON сохраняются исходные `null`.
В консоли остаются короткие сообщения без полного JSON.
При отказе проверки истории (например, неверный `ASSETCODE`) сохраняются
дата, SECID проблемной строки, `request_url` и исходный JSON страницы в `response`.
Это позволяет определить, какая именно строка ISS вызвала остановку.

При начале каждой загрузки оба журнала инструмента **перезаписываются**:
они содержат только сведения последнего запуска. Резервные копии предыдущего
запуска `.1`, `.2`, `.3` удаляются; посторонние файлы в папке не затрагиваются.
Каждый скрипт очищает только журналы своего инструмента.
Внутри одного запуска при достижении 5 МиБ файл переносится в резервную копию
`.1`; сохраняются до трёх копий `.1`, `.2`, `.3` с данными только этого запуска.
Таким образом, размер журнала ограничен и при длительной загрузке.
Просмотр `--help` и отказ проверки параметров журналы не очищают.
Папку можно изменить через `--log-dir`. Строка итога `неполных дней: 15`
означает, что 15 дат не удалось записать полной парой; это не полностью
успешная загрузка. В таком случае код выхода — `1` и печатается путь к журналу.

## Структура SQLite 3

Основная таблица **`Day`** содержит только запрошенные поля:

| Поле | Тип | Содержание |
|---|---|---|
| `TRADEDATE` | `TEXT NOT NULL` | Дата торгов, `YYYY-MM-DD` |
| `SECID` | `TEXT NOT NULL` | Полный код из ISS, включая архивный суффикс при его наличии |
| `OPEN` | `REAL NOT NULL` | Цена открытия либо отмеченная подстановка |
| `LOW` | `REAL NOT NULL` | Минимальная цена либо отмеченная подстановка |
| `HIGH` | `REAL NOT NULL` | Максимальная цена либо отмеченная подстановка |
| `CLOSE` | `REAL NOT NULL` | Цена закрытия либо отмеченная подстановка |
| `VOLUME` | `INTEGER NOT NULL` | Объём из ISS; 0 у подставленной свечи без сделок |
| `OPENPOSITION` | `INTEGER NOT NULL` | Открытые позиции, как возвращает ISS, включая ноль |
| `SHORTNAME` | `TEXT NOT NULL` | Краткое имя контракта из ISS |
| `LSTTRADE` | `TEXT NOT NULL` | Последний день торгов, `YYYY-MM-DD` |

Первичный ключ — **`(TRADEDATE, SECID)`**, поэтому два контракта одного дня
сохраняются одновременно без дублей. SQLite хранит даты в ISO-формате.
Таблица `Contracts` содержит кеш описаний, `Metadata` — код базового актива,
чтобы исключить случайное использование одной БД скриптами разных инструментов.
Таблица `EmptyWeekends` содержит `TRADEDATE` (первичный ключ) и `CHECKED_AT`
(момент подтверждения пустого ответа с московским смещением `+03:00`).
Таблица `FilledQuotes` содержит `TRADEDATE`, `SECID` (составной первичный ключ),
`SOURCE_TRADEDATE`, `SOURCE_CLOSE`, `ORIGINAL_ROW` (JSON) и `FILLED_AT`.
Для быстрого поиска прежнего закрытия создаётся индекс `Day_SECID_TRADEDATE`.
В итоговом сообщении `пустых ответов` — число реально запрошенных пустых дат
текущего запуска, `пропущено пустых выходных` — число пропусков по этому кешу.
Несовместимая существующая БД не преобразуется автоматически: скрипт сообщает
об ошибке, нужно указать новый путь через `--db`.

Пример чтения двух контрактов дня:

```sql
SELECT TRADEDATE, SECID, OPEN, LOW, HIGH, CLOSE, VOLUME, OPENPOSITION, SHORTNAME, LSTTRADE
FROM Day
WHERE TRADEDATE = '2018-03-15'
ORDER BY LSTTRADE, SECID;
```

Пример чтения котировок с признаком подстановки:

```sql
SELECT d.*, f.SECID IS NOT NULL AS IS_FILLED, f.SOURCE_TRADEDATE, f.SOURCE_CLOSE
FROM Day d
LEFT JOIN FilledQuotes f ON f.TRADEDATE = d.TRADEDATE AND f.SECID = d.SECID
ORDER BY d.TRADEDATE, d.LSTTRADE;
```

## Проверки

```powershell
python -B -m unittest discover -s MOEX_ISS_API_quote_downloader_day2/tests -v
```

Описание проверок — в [tests/README.md](tests/README.md).

Первоначальная версия ошибочно отбрасывала архивные коды с суффиксом `_2018`
и могла записать за даты 2018 года дальние серии 2019 года. Ограничение на
формат `SECID` удалено; добавлена проверка по реальному ответу ISS,
предоставленному пользователем. Если БД успела получить такие неверные пары,
остановите прежний запуск и начните загрузку с новой БД: даты с двумя полными
строками обычная докачка не перепроверяет.

Прямые запросы из среды агента к `iss.moex.com` завершаются тайм-аутом,
поэтому проверка исправления выполнена на сохранённом ответе MOEX за 03.01.2018:
выбраны `RIH8_2018` и `RIM8_2018`, проверены все десять записанных полей.
Для этой проверки истории ответы описаний контрактов задаются тестом.
